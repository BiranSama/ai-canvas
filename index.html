创作现场

一句话同时包含保留、排版、参考与生成。

“保留主体，把标题收小一点。沿用这个构图，再试一版清晨的光。”——AI Canvas 将这些决定落在同一份可编辑的 Scene 中：Agent 与鼠标操作同一组对象，参考编译器组织生成上下文，结果回到画布成为下一次创作的起点。

对话、画布、生成。

  1. 01 · 对话

    表达意图，检查真实动作。

    文档式创作记录，不是聊天气泡墙。你说清目标，Agent 回执它实际做了什么：动作、范围、对象、结果、费用与外发摘要，以及可用的撤销、定位、继续。右侧是同一份 Scene 的实时画布，不是静态副本。

    • 审阅 · 每步确认
    • 协作 · 低风险自动
    • 自动 · 边界内连续
    • 修正本轮
    • 补充本轮
    • 排到下一轮
    • 立即停止

  2. 02 · 画布

    精确控制，人工接管同一份作品。

    选择、移动、缩放、分组、排序、裁剪、编辑文字、绘制草图与蒙版、放置光影。文字与形状保持可编辑；模型返回的成图以图片元素继续参与创作。工具栏、检查器与创作输入是三座独立的光学工具岛。

    • 文字 T

    • 主体占位
    • 光影
    • 蒙版

  3. 03 · 生成

    探索方向，延续分支。

    配置一次请求，观察一个真实任务，比较结果，继续变化，把结果放回画布并导出。结果进入「结果家族」：参考、当前、父子变化与恢复形成可理解的血缘。失败时保留原 Prompt、参考与参数，说明真实失败阶段。

唯一的标志性元素

一条光迹，只在真实动作
与真实对象之间出现。

大胆只花在一个地方。当 Agent 的操作触及画布对象时，一条极细、低饱和的光谱轨迹从创作输入延伸到被影响的对象，然后自行收束。它从不无中生有：没有真实活动、没有真实受影响的元素，就没有光迹。

    Reference Compiler

    The scene is a source language.

    画布同时承载几何、语义与视觉证据。一次生成需要知道主体在哪里、哪些元素互相遮挡、哪些文字必须准确、哪些辅助对象不应出现在成图里。参考编译器把这些信息编译为语义包与视觉参考，再按 Provider 能力组织请求上下文。

      Scene

      可编辑的结构化作品：元素、变换、层级、语义角色、参考策略与来源。

      idtypesemanticRolereferencePolicytransformzIndexopacityblendModeprovenance

    2. 01

      Prompt IR

      布局、层次、遮挡与保护意图可以被继续处理的中间表示。

      boundszIndexrelationsocclusionsprotectedElementIdspresentation

    3. 02

      Prompt Package

      构图、文字、风格与禁止项分别表达，而不是揉成一段提示词。

      compositionContracttextContractstyleBiblenegativeConstraints

    4. 03

      Reference Manifest

      区分参考素材的用途，并保留来源关系；素材读取经过内容哈希核对。

      appearance-compositesemantic-sheetsource-imagesketch-underlaymask

    5. 04

      Provider Compiled Prompt

      在具体服务能力下形成提示内容与限制说明；不支持的能力不会被假装支持。

      promptnegativePromptreferenceModewarnings

    reference-only 元素可成为语义引导；隐藏、排除、蒙版与分组元素的 presentation 可为 omitted——它们仍可携带结构或保护信息，但不会被直接画成编辑器控件。

    编译结果同时携带 sceneId 与 sceneRevision。场景版本改变时请求随之更新，不能只更新说明而未更新请求。

    结构参考、视觉参考、同时参考、Prompt Package、历史结果与编辑范围共同约束生成；草图探索与高质量定稿职责明确。

    执行契约

    A suggestion becomes a checked mutation.

    Agent 的修改先表达为有作用域的命令，再经过策略、锁定和版本校验。预览保存操作批次、结果摘要与反向补丁；提交时，Main 再次核对权威 Scene 与执行结果。这条链路解决一个具体冲突：模型规划之后，用户可能已经把画布改了。旧计划不能假装这些修改不存在。

    校验点实现约束
    版本expectedSceneRevision 必须与当前权威 Scene 一致；预览后发生人工编辑，提交也会再次检查。
    作用域与权限scope、元素锁定、保护与工具策略参与预览许可判断。

    生成运行时

    A network timeout is not proof of non-submission.

    生成任务保留请求身份、提交状态、结果与来源关联。队列必须区分「确定未发送」和「可能已经发出」，因为一次普通的重试可能变成第二笔付费请求。

    有界付费

    请求数、图片数与费用上限由执行策略约束。自动模式达到任一限制后停止并请求决定。未知费用必须明确标记，不伪造精确金额。

    运行边界

    Main 是权威。
    Renderer 看不到密钥。

    Main 负责 Scene、持久化、凭据与外部请求。Renderer 通过 Preload 与窄 IPC 接口操作，窗口开启 sandbox、context isolation 并关闭 Node integration。本地优先指项目存储与控制边界；在线推理仍会发送所需提示词与参考内容到你自己配置的服务。

    • Owner Full 是当前项目内的完整产品能力，不是操作系统管理员权限。

    Provider

    两个可替换的配置槽，
    不是产品的中心。

    产品保持一个语言模型模块和一个图片模型模块。你配置名称、协议、Base URL、模型、超时、并发、能力与凭据；Runtime 根据已保存配置注册对应实现。在线能力使用你自己的模型服务与额度。

    语言模型

    • ark-responses火山方舟 Responses
    • openai-responsesOpenAI Responses 兼容
    • openai-chat-completionsOpenAI Chat Completions 兼容

    推理强度 auto → max · 图片细节 auto / low / original · 流式或缓冲传输，连接、首事件、空闲超时可配置。

    图片模型

    • ark-seedream火山方舟 Seedream
    • openai-imagesOpenAI Images 兼容
    • task-images异步任务式图片协议

    文生图、参考图、编辑、组图分别进行能力门禁；无 Key 时项目、画布与离线 Agent 仍可用，状态诚实。

    协议名称相同不保证各服务实现都兼容。参考图、蒙版、编辑和流式输出取决于具体服务能力及实际响应。真实连接验证只使用已保存配置，经用户二次确认后最多发送一个极小请求，失败不自动重试。
